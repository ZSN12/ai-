本项目是一款基于"规则引擎 + 大模型 (LLM)" 集成架构的转人工归因分析平台。专为电商客服场景设计，采用前后端分离架构，通过多线程异步调度、语义聚类去重与人工纠错反哺机制，实现海量客服对话数据的高效分类质检，替代传统人工归因复盘。

##  核心策略模块 

### 1.  专家投票仲裁系统 
* **仲裁逻辑**：构建了“硬规则过滤 -> 历史语义匹配 -> LLM 深度推理”的高性能漏斗架构。
* L1 规则引擎：毫秒级拦截高频确定性词汇，保障零成本响应。
* L2 语义匹配 (Business Memory)：利用SimilarityMatcher检索数据库中历史人工纠错的“黄金案例”，通过向量相似度实现业务记忆，跳过重复的AI 推理。
* L3 LLM深度推理：针对前两层无法判定的复杂长尾意图，调用 LLM 进行语义最终裁决。
* **技术实现**：利用 TF-IDF 字符级向量化与余弦相似度构建动态检索索引，通过加权投票机制实现多源结果的置信度博弈。
* **解决痛点**：规避了LLM幻觉，更通过“人工反馈->语义沉淀->自动复用”的闭环，解决了AI系统无法处理特定业务私有知识的难题。

### 2.  语义聚类去重引擎 
* **算法方案**：利用 **TF-IDF + 余弦相似度 ** 对海量会话进行特征提取与预处理。
* **商业价值**：精准识别相似度 > 0.85 的重复咨询，同簇会话仅调用一次 LLM，将单位质检成本压榨至极限。

### 3.  工业级并发与背压控制 
* **并发安全**：采用 **SQLite WAL 模式** 与自定义连接池技术，彻底解决多线程并发下的数据库读写冲突。
* **流量削峰**：设计 **Semaphore (信号量) 背压机制**，确保 AI 消费速度与本地大文件读取速度保持平衡，系统在满载高压下依然稳如磐石，拒绝 OOM 内存溢出。

### 4. Human-in-the-loop 人工反馈闭环
* **业务记忆**：弃用死板的静态规则，引入 SimilarityMatcher 历史相似度匹配机制。
* **精度进化**：支持质检结果人工修正，系统自动提取纠错数据的特征向量参与后续仲裁投票。实现“越用越准”，使高成本 LLM 的调用比例持续下降。

##  技术底座 

* **产品前端**：Vue3 + Vite + Element Plus 
* **AI 引擎**：DeepSeek API (Few-shot Learning / Prompt Engineering)
* **后端架构**：FastAPI + Python 3.9+ (RESTful API 设计，异步并发调度)
* **数据存储**：SQLite (高并发 WAL 模式，支持Checkpoint检查点)
* **数据处理**：Pandas, scikit-learn (特征向量化与清洗)
